Q1. Pipelining Basics, Speedup, and Hazards (Numerical & Conceptual)

1. Basic Concept

Pipelining overlaps the execution of multiple instructions by dividing the instruction cycle into distinct stages (e.g., Fetch, Decode, Execute, Write-back). It increases throughput (instructions completed per unit time) but does not reduce latency (time for a single instruction).

2. Speedup Formula

Non-pipelined time: T_n = n × t_n Pipelined time: T_p = [k + (n - 1)] × t_p Speedup (S) = T_n / T_p Ideal Speedup (for large n) ≈ k (number of stages)

3. Numerical Example (from your papers)

Q: A k-stage pipeline where each stage requires ts ns, and a non-pipelined processor executes one task in tpp ns. Derive the speedup expression and state the ideal speedup.

  • Total time for n tasks (pipelined): \(T_p = (k + n - 1) \times t_s\)
  • Total time for n tasks (non-pipelined): \(T_n = n \times t_{pp}\)
  • Speedup: \(S = \frac{n \times t_{pp}}{(k + n - 1) \times t_s}\)
  • Ideal speedup (as n → ∞): If \(t_{pp} = k \times t_s\), then \(S \approx k\).

Practical factors preventing ideal performance: Pipeline hazards (structural, data, control), stage imbalance, and pipeline fill/drain time.

Q2. Data Hazards, Operand Forwarding & Side Effects

1. What is a Data Hazard?

A data hazard occurs when an instruction depends on the result of a previous instruction that has not yet completed its execution. The most common is RAW (Read-After-Write).

2. Hazard Example & Solution

Given Sequence:
I1: R1 ← R2 + R3
I2: R4 ← R1 + R5
I3: R6 ← R1 + R7

  • Hazard Identified: I2 and I3 both depend on R1 produced by I1. This is a RAW hazard.
  • Solution 1: Operand Forwarding (Bypassing) — The result from I1's ALU output is forwarded directly to I2 and I3's ALU inputs without waiting for the write-back stage.
  • Solution 2: Stalling — If forwarding hardware is not available, the pipeline must insert bubbles (stall) until R1 is written back.

3. Side Effects

A side effect occurs when an instruction changes a register or flag other than its explicitly named destination.

  • Condition Code Flags: e.g., `ADD` modifies the Carry Flag, which might be used by a subsequent `ADDC`.
  • Autoincrement/Autodecrement: e.g., `LOAD R1, (R2)+` implicitly modifies R2.

Q3. Control Hazards, Branch Prediction & Delayed Branching

1. What is a Control Hazard?

Occurs when a branch or jump instruction changes the program counter. The pipeline has already fetched sequential instructions (wrong path), which must be flushed if the branch is taken. This wastes cycles called the branch penalty.

2. Solutions

  • Instruction Queue (Prefetching): The fetch unit continuously fills a queue. Even if a branch causes a stall, the pipeline can draw from the queue, minimizing the visible penalty.
  • Delayed Branching: The compiler places a useful instruction in the delay slot (immediately after the branch). This instruction is always executed, regardless of whether the branch is taken or not.
  • Static Branch Prediction: Simple default (e.g., "always assume not taken"), or compiler inserts a prediction bit.
  • Dynamic Branch Prediction: Hardware tracks history using a 1-bit predictor (flips on misprediction) or 2-bit predictor (requires two mispredictions to flip state; more stable).

Q4. Flynn's Taxonomy (SISD, SIMD, MISD, MIMD)

Classifies parallel architectures based on Instruction Streams and Data Streams.

Class Instruction Stream Data Stream Typical Organization
SISD Single Single Uniprocessor (von Neumann).
SIMD Single Multiple Vector/Array processors (lockstep execution).
MISD Multiple Single Theoretical only (no commercial implementation).
MIMD Multiple Multiple SMP, Multi-core, Clusters (most common).

Data Flow: In SIMD, one control unit broadcasts the same instruction to multiple processing elements, each working on different data. In MIMD, each processor has its own control unit, executing different instructions on different data.

Q5. Multiprocessors: SMP, UMA vs. NUMA, & Amdahl's Law

1. Symmetric Multiprocessor (SMP)

  • Two or more comparable processors sharing main memory and I/O.
  • "Symmetric" means all processors are equal (no master/slave).
  • Managed by a single integrated OS.
  • Bottleneck: The shared bus becomes a bottleneck as processors are added.

2. UMA vs. NUMA

  • UMA (Uniform Memory Access): All processors access a single shared memory with equal latency. (e.g., standard SMP).
  • NUMA (Non-Uniform Memory Access): Memory is distributed. A processor accesses its local memory quickly, but remote memory (another processor's memory) takes longer. Scales better than UMA.

3. Amdahl's Law

The speedup of a program is limited by its serial fraction.

Speedup S(N) = 1 / [(1 - f) + (f / N)] Where f = parallelizable fraction, N = number of cores. Max Speedup = 1 / (1 - f)

Q6. Cache Coherence & Multicore Organization

1. The Cache Coherence Problem

In a multicore system, each core has a private cache. If Core 1 modifies a shared variable in its cache, Core 2's cache still holds the old (stale) value. All processors must observe a consistent value for shared memory.

2. Solutions

  • Snoopy Protocol: Caches monitor (snoop) the shared bus. If a write occurs, other caches invalidate or update their copies (e.g., MESI protocol). Good for small bus-based systems.
  • Directory Protocol: A central directory tracks which caches hold which blocks. Targeted messages are sent to only those caches. Scales better for large systems.

3. Multicore Cache Organization

  • Private L1: Always private to each core.
  • L2/L3: Can be private or shared. A shared L3 allows cores to reuse data and dynamically allocate cache capacity, but requires coherence management.

Q7. Graphics Processing Unit (GPU) Architecture

1. CPU vs. GPU Structure

  • CPU: Latency-oriented. Large control unit (for complex branching), large cache, few powerful ALUs.
  • GPU: Throughput-oriented. Minimal control unit, small cache, hundreds/thousands of simple ALUs.

2. GPU Architecture Fundamentals

[SM] [SM] [SM] [SM] ← Streaming Multiprocessors (each has ALUs, scheduler, L1 cache) \ | | / [ Shared L2 Cache ] | [ High-Bandwidth DRAM ]
  • Streaming Multiprocessors (SMs): The building blocks of the GPU. Each executes instructions and contains multiple ALUs and a private L1 cache.
  • L2 Cache: Shared by all SMs.
  • DRAM: Main GPU memory. High bandwidth.

Latency Hiding: GPUs hide memory latency by switching to other threads while waiting for data, rather than trying to reduce the latency.

3. Discrete vs. Integrated

  • Discrete: Separate chip, dedicated VRAM, high performance, high power, PCIe overhead.
  • Integrated: Same chip as CPU, shares DRAM, lower performance, lower power, no PCIe overhead.
