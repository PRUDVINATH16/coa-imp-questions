Q1. System Bus Components & Communication Bottleneck

1. What is a System Bus?

A system bus is a shared communication pathway (a collection of parallel electrical wires) connecting the major components of a computer: the Processor (CPU), Main Memory, and I/O Devices.

2. Main Components (Bus Lines)

  • Address Lines: Identify the source or destination (e.g., memory address).
  • Data Lines: Carry the actual information (instruction or data word) being transferred.
  • Control Lines: Specify the type of operation (Read, Write, Interrupt) and synchronize the transfer.

3. Why is a Bus a Communication Bottleneck?

  • A bus is a shared resource. Only one bus master (e.g., CPU or DMA) can control it at a time.
  • As more components are added, they compete for bus access (bus contention).
  • If the bus bandwidth is insufficient, a fast CPU will have to wait for the slow bus to transfer data, slowing down the overall system.

Q2. Asynchronous Handshake Protocol

1. Role of Master-Ready and Slave-Ready Signals

In an asynchronous bus (no common clock), devices use these signals to coordinate data transfers:

  • Master-ready: Asserted by the Master. Indicates that the address, command, and (if writing) data are valid on the bus.
  • Slave-ready: Asserted by the Slave. Indicates that the slave has completed the requested operation and data is ready (or has been received).

2. Sequence of Events (Read Operation)

Time → Master: [Address/Command]----[Master-Ready]------------------[Remove Signals] Slave: [Slave-Ready]--[Data]----------[Remove Signals]
  • t0: Master places address and command on the bus.
  • t1: Master asserts Master-ready. Signal reaches the slave.
  • t2: Slave decodes address, places data on the bus, and asserts Slave-ready.
  • t3: Master receives Slave-ready, waits for setup time, and strobes (captures) the data.
  • t4: Master removes address and command (de-asserts Master-ready).
  • t5: Slave sees Master-ready go low, removes data and de-asserts Slave-ready.

Q4. Interrupts & Handling Multiple Devices

1. What is an Interrupt?

A hardware signal generated by an I/O device to alert the processor that it requires service.

2. Why Interrupts over Programmed I/O?

In Programmed I/O, the CPU wastes time in a polling loop checking device status. Interrupts allow the CPU to execute useful instructions and only service the I/O device when it is actually ready.

3. What Happens When an Interrupt Occurs?

  • The CPU finishes the current instruction.
  • It saves its state (Program Counter, Processor Status) on the stack.
  • It jumps to the Interrupt Service Routine (ISR).
  • After the ISR finishes, the CPU restores its state and resumes the original program.

4. Handling Multiple Interrupts

  • Priority: High-priority devices are serviced before low-priority ones.
  • Interrupt Nesting: A high-priority interrupt can interrupt the ISR of a low-priority device.
  • Vectored Interrupts: The device sends a code (vector) so the CPU knows exactly which ISR to execute (no need to poll).
  • Daisy Chaining: The INTA (acknowledge) signal passes through devices physically closest to the CPU first. The closest device has the highest priority.

Q5. UART and USART

1. Definitions

  • UART (Universal Asynchronous Receiver/Transmitter): A standard serial interface for low-speed devices. It performs serial-to-parallel and parallel-to-serial conversion using asynchronous start-stop bits.
  • USART (Universal Synchronous/Asynchronous Receiver/Transmitter): Supports both synchronous and asynchronous serial communication.

2. Working Principle of a UART

CPU Data Bus (Parallel) ────> [DATAOUT] ──> [Shift Register] ──> (Serial TX) CPU Data Bus (Parallel) <──── [DATAIN] <── [Shift Register] <── (Serial RX)
  • Transmitter: CPU writes a byte (parallel) to the transmitter register. It is loaded into a shift register and shifted out one bit at a time (serial). Start/Stop bits are added.
  • Receiver: Data arrives serially into a shift register. Once 8 bits are collected, the byte is moved to the receiver register for the CPU to read.

3. How USART Maintains Data Integrity

In synchronous mode, the USART uses a continuous clock signal to stay in perfect sync with the receiver, preventing bits from being misread over long distances. It also uses error-checking (parity) and can use special synchronization characters (sync bytes) to ensure the receiver knows exactly where data blocks begin and end.

Q6. RAID Techniques

1. What is RAID?

Redundant Array of Independent Disks. A system that uses multiple physical disks, viewed as a single logical disk, to improve performance, reliability, and capacity.

2. RAID Levels

RAID 0 — Striping (Performance)

  • Data is divided into strips and distributed across all disks in parallel.
  • Performance: Excellent (parallel transfer).
  • Reliability: None. If one disk fails, all data is lost.

RAID 1 — Mirroring (Reliability)

  • Every logical strip is duplicated on a mirror disk.
  • Performance: Good read performance (can read from either copy).
  • Reliability: Excellent (survives 1 disk failure). Cost is high (100% storage overhead).

RAID 5 — Distributed Parity (Balanced)

  • Uses block-level striping and distributes parity across all disks (no single parity bottleneck).
  • Performance: Good for reads, moderate for writes (requires parity calculation).
  • Reliability: Can survive 1 disk failure (data is rebuilt using XOR parity).

RAID 6 — Dual Distributed Parity (High Fault Tolerance)

  • Uses two independent parity calculations (P and Q) distributed across disks.
  • Performance: Slower writes (double parity calculation).
  • Reliability: Can survive two simultaneous disk failures. Used for mission-critical data.
